# Epholang website

Статический двуязычный сайт существующего репозитория Epholang. Концепция «Явность в коде»: Astro, обычный CSS, Shiki с исходной TextMate-грамматикой Epholang, Lucide, Inter и JetBrains Mono без лигатур.

## Локальный запуск

Нужны Node.js 24 и npm. Из корня репозитория:

```sh
cd website
npm ci
npm run dev
```

Откройте `http://localhost:4321/epholang/`. Корень содержит обычные ссылки на русский и английский разделы и работает без JavaScript. Сохранённый выбор языка используется при следующем посещении корня. Язык браузера только выделяет рекомендованную ссылку при первом посещении; автоматического перенаправления без сохранённого выбора нет.

```sh
npm run check
npm run build
npm run check:dist
npm run preview
```

`check` проверяет Astro/TypeScript, данные и обработку вложенных комментариев/интерполяции. `check:dist` проверяет все 14 HTML-страниц, метаданные, локальные ссылки и наличие ресурсов. Rust для этих команд не нужен. Сборка не обращается к GitHub API.

## Структура

- `src/pages/` — таблица маршрутов, корень и 404.
- `src/components/` — шесть небольших представлений страниц, общий layout и блок кода.
- `src/data/site.ts` — подписи, переводы интерфейса, особенности, описания примеров; пояснения страниц находятся рядом с разметкой в компонентах.
- `src/data/programs.ts` — чтение исходных примеров и общая команда сборки.
- `src/data/release.json` — проверенный снимок опубликованного релиза.
- `src/data/outputs.json` — результаты фактического выполнения шести детерминированных программ.
- `src/styles/global.css` — токены, типографика, компоненты и адаптивность.
- `src/scripts.ts` — меню, вкладки, копирование и языковое предпочтение.
- `scripts/` — подготовка ресурсов, проверки и обновление данных.

Чтобы добавить раздел, дополните таблицу `slugs`, обе локализации `labels`/`descriptions` в `site.ts` и представление в маршрутном файле. Ссылки строятся через `url()`. Код Epholang не переводится.

`predev`/`prebuild` копируют три оригинальных PNG из `../images/` и шрифты из зафиксированных пакетов Fontsource. Копии в `public/assets` и `public/fonts` генерируются и игнорируются Git. Лицензии шрифтов копируются рядом с файлами. Изображения не перекрашиваются. Грамматика читается напрямую из `../editors/vscode/syntaxes/`. Программы читаются из `../examples/`; их тексты не дублируются.

## Проверка примеров — отдельно от сайта

Требуются Rust/Cargo и Node.js:

```sh
# из корня репозитория
cargo build --locked
cd website
npm run examples:check
```

Исполняется семь программ. Случайное число из `06_math.epho` не сравнивается с фиксированным значением. Для осознанного обновления снимка:

```sh
node scripts/verify-examples.mjs --write
```

Просмотрите diff перед коммитом. `EPHOLANG_BIN` позволяет указать другой исполняемый файл. Снимок вывода получен на 0.2.0, commit `643c9ee1a33c13d32511004d9195db5384f6710a`, Linux x64. Исходники интерпретатора не изменялись.

## Версия и загрузки

Источник — опубликованный GitHub Release, включая prerelease. Endpoint `releases/latest` не используется. Обычная сборка и браузер посетителя читают локальный снимок.

```sh
npm run release:update -- --tag 0.2.0 --check
npm run release:update -- --tag 0.2.0
```

Первая команда проверяет опубликованные вложения, не записывая файл. Вторая обновляет `release.json`: тег, название, дату, признак prerelease, идентификаторы, размеры, digest и точные URL вложений. При неизвестном файле скрипт останавливается: добавьте в снимок явное соответствие имени, `kind` (`interpreter`/`editor`) и подтверждённой платформы, затем повторите. Платформы и архитектуры из имени не угадываются. Черновики отклоняются. При сетевой ошибке снимок не изменяется.

После нового выпуска: обновите снимок, проверьте инструкции и примеры, просмотрите diff, выполните проверки сайта и закоммитьте изменения. Новый релиз не обновляет сайт автоматически. Все страницы используют один снимок; ссылка «Все релизы» ведёт на GitHub.

В средах с обязательным HTTP-прокси для Node.js 24 может потребоваться `NODE_USE_ENV_PROXY=1`. Секреты для публичного API не нужны. При ограничении частоты GitHub API повторите позже.

## Браузерные проверки

```sh
npx playwright install chromium
npm run build
npm test
```

Playwright сам запускает статический preview. Проверяются обе локализации, корень без JS, сохранение языка/отказ хранилища, вкладки с клавиатуры, Clipboard API, мобильное меню и Escape, ширины 320/390/768/1280 и увеличение текста. axe проверяет 12 локализованных страниц по доступным правилам WCAG A/AA. Автоматические проверки не заменяют полноценную ручную проверку скринридером.

## GitHub Pages

1. Добавьте изменения в существующий репозиторий Epholang.
2. В Settings → Pages выберите Source: **GitHub Actions**.
3. Слейте изменения в `main` либо запустите Website вручную на `main`.
4. Откройте `https://itsmequote.github.io/epholang/` после успешного deploy.

Настройка Pages выполняется владельцем репозитория. Секреты не требуются. Публикуется только `website/dist/`.

Workflow `website.yml` разделяет сборку/браузерные проверки и запуск Rust-примеров. Последний включается только при изменении исходников языка, примеров, снимка вывода, скрипта проверки или самого workflow, а также при ручном запуске. `ci.yml` получил только `paths-ignore` для изменений исключительно сайта; существующая матрица проверок языка сохранена. `release.yml` не изменён. Действия нового workflow закреплены SHA.

Если существующий CI является обязательной проверкой защищённой ветки, GitHub может оставлять пропущенный через `paths-ignore` workflow в состоянии Pending. В этом случае владелец должен согласовать список обязательных проверок с раздельным Website CI; настройки защиты кодом сайта не меняются.

## Диагностика

- 404/стили отсутствуют: проверьте путь `/epholang/`, `base` в Astro и путь загружаемого артефакта. Не открывайте `dist/index.html` через `file://`.
- Пропали шрифты/изображения: выполните `npm ci` и `npm run build`; подготовка копий запускается автоматически.
- Ошибка Pages deploy: проверьте Source = GitHub Actions, environment `github-pages`, разрешения и журнал workflow.
- Ошибка примеров: запускайте проверку из `website/` после `cargo build --locked`; пересмотрите снимок вместо отключения проверки.
- Ошибка API: проверьте тег, доступность GitHub и rate limit; опубликованный сайт продолжает использовать снимок.

Политика robots.txt относится ко всему домену: файл проекта доступен по `/epholang/robots.txt`, но корневой robots.txt домена GitHub Pages может управляться другим репозиторием. Sitemap также объявляется в этом файле; для поисковой консоли используйте прямой URL `/epholang/sitemap-index.xml`.

## Реальные ограничения

Онлайн-интерпретатора нет. Wiki — внешний англоязычный справочник, который пока заполнен частично. Расхождения `--help` и форматирования flt из Wiki на сайте не воспроизводятся. Windows-файл не объявляется сборкой определённой архитектуры без подтверждения. Все ограничения Alpha явно приведены на страницах.
